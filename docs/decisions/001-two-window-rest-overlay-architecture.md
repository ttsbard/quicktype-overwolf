# ADR 001: Двухоконная архитектура REST-оверлея

**Дата:** 2026-10-10  
**Уточнено:** 2026-10-21
**Статус:** accepted

## Контекст

Прототип Skald проверял захват ввода в игре без системного курсора. QuickType отделяет ввод от конкретного TTS-сервера и позволяет настроить REST/Webhook-интеграцию.

## Решение

Приложение содержит два пользовательских окна и фоновый контроллер:

- `desktop.html`: настройка GET/POST/PUT, HTTP URL, заголовков и шаблона; тест запроса; оформление оверлея и сброс геометрии.
- `overlay.html`: ввод с Enter/Shift+Enter/Escape, drag/resize, статус отправки.
- `background.html`: глобальный хоткей, жизненный цикл окон, отправка запросов и передача результата с requestId.

Локальные адреса используют `overwolf.web.sendHttpRequest`, остальные — fetch с требованиями CORS. Полное ожидание ответа ограничено 15 секундами. Автоматических повторов нет: сетевой сбой не доказывает отсутствие обработки запроса сервером.

Оверлей использует `transparent: true`, `in_game_only: false`, `grab_keyboard_focus: true` и `focus_game_takeover: "ReleaseOnHidden"`. Ввод доступен на рабочем столе и в игре; запуск приложения и клик по значку хаба открывают ввод, а кнопка ⚙ — настройки. Контроллер восстанавливает окно и вызывает bringToFront/requestOverlayFocus; минимальная версия Overwolf — 0.250.0.

## Поведение ввода

Enter блокирует редактирование до результата. HTTP 2xx сразу очищает отправленный текст при включённом clearOnSubmit; через 350 мс окно скрывается при включённом closeOnSubmit. Отдельного сообщения об успехе нет. Ошибка разблокирует поле и сохраняет текст. Escape скрывает окно только при включённом closeOnEscape; хоткей также позволяет выйти. Черновик сохраняется при скрытии в пределах текущей сессии окна, но не записывается в localStorage. Ответ dismissed-запроса игнорируется по requestId, но уже переданный запрос может быть выполнен сервером.

Повторные сообщения фокуса сохраняют pending-состояние. Каждый запрос использует снимок настроек, а успех относится только к его тексту. Настройки оформления для live-предпросмотра передаются отдельно от сохранённой конфигурации API.

Конфигурация хранится в localStorage, настройки и геометрия — в отдельных записях, чтобы одновременные сохранения не перезаписывали друг друга. Старый формат читается для совместимости. Окна обновляют только принадлежащие им поля: desktop сохраняет настройки формы, overlay — bounds/width/height. Геометрия восстанавливается при создании окна; Overwolf может скорректировать позицию по границам игры.

## Последствия

- При ожидании сети окно остаётся открытым, пока пользователь не скроет его или не придёт результат/deadline.
- Внешний сервис должен поддерживать выбранный формат тела, авторизацию и CORS для fetch.
- Поддержка зависит от совместимости игры с Overwolf. Store compliance и поведение фокуса требуют отдельного живого тестирования и ревью платформы; два окна сами по себе не подтверждают готовность публикации.
